Important limitations / residual risks
1. This environment did NOT perform a PlatformIO/ESP32 compile. A real toolchain build is mandatory before flashing.
2. No ESP32 hardware endurance run was performed here. Host models cannot emulate NimBLE/FreeRTOS/TWAI timing exactly.
3. Config is a shared legacy struct. canRxEnabled is read from the CAN task while UI/MQTT can update it; several WebUI reads also observe telemetry/config written elsewhere. Scalar ESP32 accesses are normally naturally sized, but this is not a formal C++ synchronization scheme. A full config synchronization refactor was intentionally NOT made in this final pass because it would be broad and could introduce more regression risk without a compiler/hardware test.
4. Direct persistent PowerStream CAN limit writes remain unverified and were not enabled.
5. JK dangerous writes/MOS/address/function-bit writes remain locked/read-only.
6. 332-byte bytes 300..323 remain opaque extra data; they are not interpreted.
